# A3 演示脚本、录屏提纲与现场演示清单

## 1. 演示目标

用 7 分钟展示 AdaptiveEdu 如何基于课程知识库、学习画像、知识追踪和多智能体协作，为学生生成个性化学习资源包，并完成路径绑定和反馈闭环。

## 2. 演示账号和课程准备

- 主课程：`大数据技术与应用`。
- 后端需已执行：

```bash
cd backend
uv run python tools.py create-test-data
uv run python tools.py bootstrap-course-assets --course-name "大数据技术与应用"
uv run python tools.py build-rag-index
```

- 学生需能进入 `/student/course-select` 并选中课程。

不要在视频或截图中展示真实密码、密钥或 `backend/.env`。

## 3. 启动与数据准备

```bash
cd backend
uv run python manage.py runserver 127.0.0.1:8000

cd frontend
npm run dev
```

录屏前检查：

- `/health/` 返回正常。
- `/student/agent-learning` 可打开。
- 浏览器控制台无关键错误。
- 课程已选择。
- OpenAPI lint 和前后端验证已通过。

## 5. 现场演示点击路径

1. 登录学生端并确认当前课程。
2. 打开 `/student/agent-learning`。
3. 在画像描述输入：

```text
我是软件专业学生，想两周内掌握 Spark SQL，但 HDFS 和 MapReduce 基础不太好，喜欢视频、案例和练习。
```

4. 学习目标输入：

```text
补齐 Spark SQL 查询、DataFrame 操作和项目实操能力
```

5. 勾选讲解、导图、练习、阅读、实操。
6. 点击“抽取画像”，讲解画像字段。
7. 点击“生成资源包”，讲解智能体时间线和质量分。
8. 依次展示讲解文档、思维导图、练习题、拓展阅读、代码案例。
9. 打开证据抽屉，强调 evidence 和 warnings。
10. 点击“应用到学习路径”，说明不会破坏已完成节点。
11. 打开反馈面板，提交完成状态和评分。
12. 展示效果摘要。

## 6. 讲解词

开场：

> 我们的 A3 版本不是把学生问题直接丢给大模型，而是把课程知识库、学习画像、知识追踪和学习路径结合起来，让多智能体协作生成可追溯资源包。

画像：

> 学生用自然语言描述目标、基础、短板、偏好和时间安排。系统会抽取十类画像字段，不足时生成下一轮追问。

多智能体：

> 这里的时间线展示了画像、知识检索、路径规划、资源生成、多模态表达和质量评估六类角色。每一步都有状态和摘要，便于演示和排查。

资源：

> 系统默认生成至少五类资源：讲解、导图、练习、阅读和实操。每张卡片都保留课程证据，证据为空时不会编造来源，而是显示 warning。

闭环：

> 学生可以把生成资源应用到学习路径，系统优先绑定到相同知识点节点。学习完成后提交反馈，反馈会进入资源反馈表和节点进度扩展数据，为后续画像和路径更新提供依据。

## 8. 常见失败场景与兜底话术

| 场景 | 兜底说明 |
| --- | --- |
| LLM 不可用 | 系统会使用模板化资源生成，演示重点仍是结构化资源和证据追溯 |
| 证据不足 | warnings 会提示需结合教师材料复核，不伪造来源 |
| Neo4j 未启动 | PostgreSQL 知识点和课程资源仍可支撑主流程 |
| 学生未选课 | 先进入 `/student/course-select` 选择课程 |
| 生成耗时 | 当前为同步接口，后续可扩展为 SSE/WebSocket 进度 |

## 10. PPT 大纲

1. 问题背景：高校课程资料散、学生补弱难、教师个性化成本高。
2. 系统目标：基于大模型和多智能体生成个性化资源包。
3. 技术架构：前端、后端、知识库、GraphRAG、MEFKT、LLM、Agent。
4. 课程知识库：大数据课程资产、知识点、关系、资源、题库。
5. 学习画像：自然语言画像抽取和动态更新。
6. 多智能体协作：六类角色和 trace。
7. 个性化资源生成：五类资源和证据追溯。
8. 学习路径与反馈闭环：路径绑定、反馈、效果摘要。
9. 测试验证：后端测试、前端构建、OpenAPI、浏览器巡检。
10. 创新点与未来计划：异步编排、教师审核、真实视频/语音生成。
