状态：全功能设计完成（规范 + 功能清单 + 高保真交互原型）

## 1. 产品与用户

“自适应学习”不是通用教务后台，而是围绕“知识结构、学习路径、掌握证据”运行的学习系统。

- 学生：需要立刻知道“我现在学什么、为什么、下一步是什么”。
- 教师：需要以课程为工作空间，完成内容组织、班级观察、题目与作业治理。
- 管理员：需要高密度、低干扰地完成账号、课程、班级和系统治理。

三个角色共享组件和视觉语言，但不共享同一种页面密度。学生端偏任务引导，教师端偏工作空间，管理端偏数据操作。

名称使用规则：全称只用于登录品牌区、关于信息和正式文档；导航、浏览器标题、页头和按钮使用“自适应学习”。“学习航图”是界面概念，不作为产品名。

## 2. 现状审计结论

### 2.1 结构问题优先于视觉问题

- `n-row` / `n-col` 适配器输出普通 `div`，但没有对应网格样式；桌面端本应四列的统计卡变成四个全宽卡片。
- 移动端仍保留 72px 固定侧栏，顶部课程选择、面包屑和用户菜单互相挤压。
- 页面组件同时使用旧 Element 风格属性、Naive UI 和自建适配层，响应式属性经常只读取一个值，无法按断点工作。
- 登录成功提示向 Naive UI Message 传入对象而非支持的内容类型，运行时持续产生 Vue prop 警告；反馈适配层也需要纳入结构修复。
- 当前 62 个 Vue 文件中存在 422 个硬编码颜色、151 处行内样式和 93 处 `!important`，设计令牌无法成为可信的单一来源。

因此，视觉重做之前必须先替换不可靠的布局适配层。

### 2.2 视觉语言分裂

- 全局令牌以 Fluent 蓝为主，学生页面仍大量保留绿色和 Element UI 的 `#409eff / #67c23a / #e6a23c / #f56c6c`。
- 玻璃、渐变、大圆角、阴影被同时用于背景、导航、卡片和弹层，所有元素都在争夺注意力。
- 认证页、学生仪表盘、教师仪表盘与管理仪表盘像来自不同模板。
- 字体、数字、标题与正文缺少明确角色，统计数字和业务标题经常只有字号差异。

### 2.3 信息架构和任务层级

- 学生侧栏平铺功能名称，系统结构清楚，但学习顺序不清楚。
- 仪表盘首先展示四个统计数字，而不是当前学习任务和下一步行动。
- 学习路径是全宽横向链条，长路径需要水平滚动，阶段、分支和回退原因难以理解。
- 知识图谱默认同时呈现大量节点和关系，形成“毛线团”，不能回答“我为什么要学这个”。
- AI 助手与学习路径、当前知识点、引用证据彼此割裂，页面有大面积空白却缺少对话历史和上下文。

### 2.4 可访问性与界面文案

- 部分卡片标题产生嵌套 heading，页面缺少稳定的 h1 → h2 层级。
- 多处状态只依赖颜色；图谱控制按钮使用 `+ / - / ⊡`，缺少清晰名称。
- “忘记密码”指向 `javascript:;`，属于看似可用但没有结果的控制。
- 空状态多为“暂无数据”，没有告诉用户如何继续。
- 移动端导航仍显示全部桌面菜单，触控目标和内容宽度不足。

## 3. 设计方向

### 3.1 界面概念：学习航图

把“知识图谱”从一个独立可视化页面，提升为全站的组织语言：

- 节点：知识点、任务、测评、资源。
- 路径：当前步骤、下一步、可选分支。
- 航标：薄弱点、阶段目标、教师反馈。
- 证据：题目结果、学习记录、来源资源、AI 引用。

界面不再用大量卡片表达“系统有很多功能”，而是用一条持续存在的学习轨迹表达“用户正在向哪里前进”。

### 3.2 标志性元素：学习轨迹带

学生端核心页面顶部使用一条紧凑的“过去 → 当前 → 下一步”轨迹带：

```text
已完成 8 项 ── ● 当前：Spark SQL 原理 ── ○ 下一步：阶段测试
                 预计 35 分钟            解锁 3 个知识点
```

它不是装饰，而是统一承担以下任务：

- 告知当前位置和完成原因。
- 提供唯一的主行动。
- 展示下一步及解锁条件。
- 连接路径、图谱、任务学习与 AI 助手。

视觉上的大胆只投入在这条轨迹带。其余卡片、表格和弹层保持克制。

### 3.3 自我校验

初始方案如果继续使用“大标题 + 四张统计卡 + 渐变背景”，会再次落入通用 SaaS 仪表盘。最终方案已改为以学习轨迹和证据链为中心：数字退居辅助位置，图谱关系承担真实导航功能；地图纹理只用于轨迹区域，不扩散到全站背景。

### 3.4 优秀项目基准后的优化

- 参考 Khan Academy：掌握百分比增加“接触、熟练、掌握”等级，活动后显示技能上升或下降的证据。
- 参考 Duolingo 学习路径：章节指南、新知识、复习、作业和阶段测试交错进入同一条路径。
- 参考 Open edX Studio：教师区分已保存草稿、已发布版本、定时发布和学员预览。
- 参考 Moodle：资源、实验、作业与检测直接展示可验证完成条件。
- 参考 Neo4j Bloom：图谱按学习目的切换视角，并限制每个视角中的节点和关系类型。

具体吸收与舍弃项见《前端优秀项目基准》。本项目不复制任何基准产品的品牌外观或游戏化包装。

## 4. 视觉语言

### 4.1 色彩

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 墨蓝 Ink | `#17324D` | 主标题、主导航、关键文本 |
| 航标青 Beacon | `#0B7C86` | 主操作、当前节点、焦点环 |
| 路径蓝 Route | `#3267B1` | 链接、关系线、信息状态 |
| 证据金 Evidence | `#C58A17` | 待验证、阶段测评、提示 |
| 纸面 Paper | `#F5F8FA` | 页面背景、低层级区域 |
| 警示朱 Alert | `#C44747` | 错误、薄弱点、破坏性操作 |

规则：

- 一个页面最多出现一个主强调色和一个语义色。
- 掌握状态使用“颜色 + 图标 + 文本”，不只改变圆点颜色。
- 卡片默认为白色或 Paper，不使用全局半透明玻璃背景。
- 深色模式在基础组件稳定后再实现，不与首轮重构并行。

### 4.2 字体

- 展示标题：`LXGW WenKai Screen`，仅用于学习轨迹标题、课程名和关键章节标题，体现学习笔记的人工感。
- 正文与控件：`Noto Sans SC`，保证中文密度和长时间阅读体验。
- 数据与代码：`IBM Plex Mono`，用于掌握度、时长、节点编号和技术片段。
- 未加载 Web 字体时回退到系统中文字体，不阻塞首屏。

### 4.3 尺度

- 字号：12 / 14 / 16 / 20 / 28 / 36。
- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48。
- 圆角：10（控件）/ 14（卡片）/ 18（大型面板），不再默认 20px 以上。
- 阴影：只用于浮层、拖拽和悬停中的可操作对象；常规卡片使用 1px 边框。
- 内容最大宽度：学生端 1440px；教师、管理数据表可使用全宽。

### 4.4 动效

唯一的编排动效是学习轨迹带在数据就绪后从已完成节点绘制到当前节点，时长 320–480ms。

- 页面切换只使用 120–180ms 淡入，不横向滑动。
- 卡片悬停不统一上浮；只有可点击卡片显示位移或边框反馈。
- 支持 `prefers-reduced-motion`，关闭路径绘制和位移动画。

### 4.5 内容密度与完整性

原型和生产页面不能只放少量示意内容。默认有数据状态遵循以下基线：

| 页面类型 | 首屏或首批内容 | 每项必须展示 |
| --- | --- | --- |
| 资源库 | 8–12 项、至少 5 种资源类型 | 标题、类型、知识点、来源、用时或大小、进度、操作；推荐项增加原因 |
| 知识图谱 | 当前章节 12–24 个节点 | 名称、掌握状态、关系类型；选中后显示证据、资源和学习意义 |
| 作业列表 | 5–10 项或完整空状态 | 截止时间、作答进度、提交状态、尝试次数和反馈入口 |
| 课程 / 班级 | 4–8 项摘要 | 当前状态、进度、待办和进入动作 |
| 教师 / 管理表格 | 首批 8–20 行 | 筛选、排序、状态、作用范围和行操作 |
| 详情页 | 摘要 + 关系 + 记录 + 动作 | 不只展示描述文本，必须能回答现状、来源、影响和下一步 |

移动端不通过删除信息降低密度：次要元数据折叠到第二行或详情抽屉，列表和图谱使用容器内滚动。

## 5. 应用壳层与导航

### 5.1 桌面端

```text
┌──────────── 224 ────────────┬──────────────────────────────────────────┐
│ 品牌 / 当前角色             │ 课程上下文        搜索       用户菜单    │
│                              ├──────────────────────────────────────────┤
│ 今天                         │ 页面标题 / 辅助动作                      │
│  · 学习工作台                │                                          │
│  · 当前路径                  │ 主内容                                   │
│ 学习                         │                                          │
│  · 知识与资源                │                                          │
│  · 测评与作业                │                                          │
│ 洞察                         │                                          │
│  · 学习画像                  │                                          │
└──────────────────────────────┴──────────────────────────────────────────┘
```

- 顶栏只保留课程上下文、全局搜索和用户菜单。
- 面包屑仅用于教师/管理深层工作区；学生一级页面不显示“首页 / 页面名”。
- 侧栏按任务分组，不按后端模块分组。
- 折叠侧栏只在桌面存在，并提供稳定 tooltip。

### 5.2 移动端

- 完全移除固定左侧栏。
- 底部导航保留：今天、路径、知识、我的；其他功能放入“更多”。
- 顶部只显示当前课程和页面标题，用户菜单进入“我的”。
- 表格转换为字段卡或允许受控横向滚动，不压缩到不可读。

## 6. 关键页面设计

### 6.1 学生学习工作台

页面唯一目标：让学生在 5 秒内开始最重要的学习任务。

```text
┌ 学习轨迹带 ───────────────────────────────────────────────────┐
│ 已完成 8 项  ● Spark SQL 原理  ○ 阶段测试    [继续学习 35 分钟] │
└───────────────────────────────────────────────────────────────┘
┌ 当前任务 8/9 ───────────────────────┬ 本周证据 ────────────────┐
│ 学习目标、资源、完成条件             │ 掌握 +2 / 薄弱 1 / 6h    │
│ [开始学习] [查看为什么推荐]          │ 查看学习画像              │
└──────────────────────────────────────┴──────────────────────────┘
┌ 待办与截止日期 ─────────────────────┬ 最近反馈 ─────────────────┐
│ 作业、测评、教师任务                 │ 教师反馈、AI 引用、错题     │
└──────────────────────────────────────┴──────────────────────────┘
```

- 四个统计卡合并为一条 `MetricStrip`，不占据首屏主体。
- “快捷入口”取消；导航和上下文动作已经承担入口职责。
- “继续学习”是唯一主按钮，作业按钮为次级。

### 6.2 学习路径

- 桌面端使用纵向主路径 + 右侧当前节点详情，避免长链水平滚动。
- 已完成节点折叠为阶段摘要；当前阶段展开；未来阶段只显示解锁条件。
- 分支路径明确标识“必修 / 推荐 / 补强”，并解释推荐原因。
- 跳过操作必须说明影响，完成后显示路径如何调整。

```text
阶段 1 基础建立  ✓ 5/5
阶段 2 Spark 能力  3/4
  ├─ ✓ Spark 核心模型
  ├─ ✓ RDD 操作
  ├─ ● Spark SQL 原理      [当前]
  └─ ○ 阶段测试            [完成当前任务后解锁]
阶段 3 综合实践  0/3
```

### 6.3 知识图谱

默认展示当前章节的 12–24 个节点，不直接绘制全课程节点。

- 当前章节视图呈现章节结构；选择节点后切换为一跳邻域并允许逐层展开。
- 提供“当前章节、一跳邻域、薄弱点、全局地图”四个明确视图。
- 选中节点后右侧详情面板显示：解释、掌握证据、关联资源、为什么关联、加入路径。
- 搜索结果先以列表呈现，选择后再定位图节点。
- 图例可交互过滤；缩放按钮使用“放大、缩小、适合画布”的可访问名称。

### 6.4 AI 学习助手

```text
┌ 当前上下文 ───────┬ 对话 ───────────────────────┬ 证据与引用 ─────────┐
│ Spark SQL 原理     │ 提问 / 回答 / 建议动作       │ 图谱节点、课程资源   │
│ 路径第 8/9 项      │                              │ 引用段落、可信状态   │
│ 薄弱：执行计划     │ [输入问题……]        [发送]  │ [加入学习任务]       │
└────────────────────┴──────────────────────────────┴─────────────────────┘
```

- 不再分成“先搜索图谱”和“再问答”两个孤立面板。
- 每个回答必须显示所用课程、知识点和来源；无证据时明确标记为通用回答。
- 推荐问题来自当前任务，而不是通用占位文案。
- 移动端只显示对话，当前上下文与证据使用底部抽屉。

### 6.5 教师端

教师端以“课程工作空间”为核心，不在全局侧栏平铺题库、资源、图谱、作业的重复入口。

```text
大数据技术与应用 / 课程工作空间
[概览] [学生] [知识图谱] [资源] [题库] [作业] [设置]
```

- 概览优先展示待处理事项、班级风险、内容完整度。
- 编辑页面使用稳定的保存栏，明确“未保存 / 保存中 / 已保存 / 保存失败”。
- 批量操作始终显示选中数量、影响范围和撤销/确认路径。

### 6.6 管理端

- 取消大面积欢迎 Hero 和彩色统计卡。
- 使用紧凑 KPI 行、筛选栏、数据表、详情抽屉。
- 危险操作集中到详情抽屉，不与常用操作并排。
- 系统日志提供时间、操作者、模块、结果四个固定筛选维度。

### 6.7 认证页

- 左侧不再用表情符号宣传功能，改为一张简化的课程知识路径示意图。
- 登录区域只保留账户字段和必要的操作，不解释系统会如何分流角色。
- “忘记密码”在功能未实现前显示为说明文本或移除，不保留空链接。
- 移动端只保留品牌标识和表单，示意图隐藏。

## 7. 组件与状态体系

首轮应建立以下基础组件，页面不得自行复制同类结构：

| 组件 | 职责 |
| --- | --- |
| `AppShell` | 桌面侧栏、移动底栏、顶部上下文 |
| `PageHeader` | 页面标题、说明和最多两个动作 |
| `LearningTrail` | 过去、当前、下一步及解锁条件 |
| `MetricStrip` | 紧凑指标与趋势，不承担导航 |
| `TaskCard` | 当前任务、完成条件、预计时长 |
| `EvidencePanel` | 掌握证据、引用、反馈与来源 |
| `StatusPill` | 颜色、图标、文本一致的状态表达 |
| `FilterBar` | 搜索、筛选、批量操作 |
| `DataTable` | 教师/管理端表格与移动降级 |
| `EmptyState` | 解释原因并给出下一步动作 |
| `ErrorState` | 明确失败对象、原因和重试动作 |
| `Skeleton` | 与最终结构一致的加载占位 |

状态规范：

- Loading：保留最终布局尺寸，避免页面跳动。
- Empty：说明为什么为空，以及用户能做什么。
- Error：指出哪项数据失败，保留其他可用内容。
- Disabled：解释解锁条件，不只降低透明度。
- Success：动作名称与结果文案保持一致，例如“发布”→“已发布”。

## 8. 实施顺序

### Phase 0：结构可靠性

- 冻结 `naive-element-adapter` 的新增使用。
- 用原生 Naive UI 或自建 `Grid / Stack / Cluster` 替换 `n-row / n-col` 兼容布局。
- 重做 `AppShell` 响应式行为；移动端移除固定侧栏。
- 为登录、学生工作台、学习路径建立桌面/移动视觉回归截图。

完成标准：1280px 和 390px 下无内容挤压、横向溢出或错误全宽网格。

### Phase 1：设计令牌与基础组件

- 合并 `variables.css`、Fluent tokens 与 Naive overrides。
- 替换 Element 遗留色和无意义 `!important`。
- 实现 `PageHeader / StatusPill / EmptyState / MetricStrip / FilterBar`。
- 建立可见键盘焦点、语义标题和 reduced-motion 基线。

### Phase 2：学生主闭环

- 学习工作台。
- 课程选择与班级空间。
- 初始测评、测评报告与学习画像。
- 学习路径、任务学习与阶段测试。
- 课程资源、在线作业、答题与反馈报告。
- AI 学习助手与个性化智能体。
- 个人设置和学习偏好。

### Phase 3：知识图谱与 AI

- 图谱渐进式展示与节点详情。
- AI 对话、上下文和证据面板合并。
- 统一 GraphRAG 来源、置信状态和失败降级。

### Phase 4：教师与管理工作空间

- 教师课程工作空间。
- 表格、筛选、批量操作和保存状态。
- 管理端高密度治理页面。

## 9. 设计验收标准

- 学生进入首页后 5 秒内能识别当前任务和唯一主行动。
- 390px 宽度下没有固定侧栏、水平页面滚动或被遮挡控件。
- 任何页面不超过一个主按钮；其他动作按次级、文本、危险层级呈现。
- 知识图谱默认节点数量受控，选中节点后能解释其关系和学习意义。
- 知识图谱当前章节视图展示 12–24 个节点，并明确区分先修、组成、后续关系。
- 资源页首批至少展示 8 项，推荐资源必须给出知识点、来源、时长或大小、进度和推荐依据。
- 详情页能够回答当前状态、证据来源、关联影响和下一步行动，不能只展示一段说明。
- AI 回答能区分课程证据与通用回答。
- 所有可交互元素支持键盘操作和可见焦点。
- 状态不只依赖颜色；空、错、加载、禁用均有明确文案。
- 新页面不新增硬编码品牌色、行内布局样式或 `n-row / n-col` 适配依赖。

## 10. 设计冻结与实施交接

以下决策已经通过原型确认，生产实现阶段不再重新选择方向：

- 产品名称固定为“知识图谱驱动的个性化自适应学习系统”，系统内简称“自适应学习”。
- “学习航图”只作为界面组织概念，标志性元素为“学习轨迹带”，不作为产品名称。
- 学生首页的第一主行动是继续当前任务，统计数字不占据首屏主体。
- 学习路径使用纵向阶段结构，不恢复长链水平滚动。
- 学习路径同时编排指南、新知识、间隔复习、应用作业与阶段测试。
- 知识图谱默认展示当前章节 12–24 个节点；选中后聚焦一跳邻域，不默认加载全课程毛线团。
- AI 助手统一展示当前上下文、对话和课程证据；移动端上下文与证据降级为抽屉。
- 教师端围绕课程工作空间组织；管理端使用紧凑 KPI、筛选和数据表。
- 教师内容编辑区必须区分草稿保存状态和学员可见版本，并提供学员预览。
- 移动端不保留固定侧栏；学生端使用四项底部导航。
- 品牌色、字体角色、间距、圆角与动效规则以本文件第 4 节为准。

允许在实现阶段调整但必须保留设计意图的内容：

- 具体文案和真实数据长度。
- 各断点的精确像素值。
- 图谱节点的布局算法和手势细节。
- 教师、管理表格在窄屏下采用字段卡还是受控横向滚动。
- 字体资源的加载方式与本地回退策略。
